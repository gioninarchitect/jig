Financial Leak Control Backbone

This page compares the requested backend architecture with what has been added to Origin Retail. The implemented model links online payments, pharmacy processing ledger, central batch inventory, package custody, refunds, returns and settlement status through persisted database records.

[ Patients ] -> [ Pharmacy_Orders ] -> [ Pharmacy_Order_Items ] -> [ Inventory_Batches ] | | | -> [ Inventory_Movements ] | -> [ Payment_Events ] -> [ Payment_Allocations ] | -> [ Order_Packages ] -> [ Package_Custody_Events ] | -> [ Pharmacy_Ledger ] -> [ Pharmacy_Settlements ] | -> [ Return_Waybills ] -> [ Refunds_Payable ] -> [ Workflow_Tickets ]

Golden Rule

Financial and physical-stock history is not overwritten. Corrective actions are represented as new balancing rows such as refund records, return waybills and inventory return movements.

Production Gate

UAT must prove every button writes to the database. A visual status change without persisted audit evidence does not pass.
