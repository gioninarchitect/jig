What is DBC?

De Bud Chef (DBC) is a full-stack cannabis retail management platform designed for multi-branch dispensary operations in South Africa. It manages everything from point-of-sale to inventory, compliance (Section 21 medical cannabis), supplier onboarding, wholesale, drive-through, and owner-level command-and-control across a branch network.

Core Differentiator: The World Model — a proprietary event-driven intelligence engine providing 5 "World First" capabilities that no competing cannabis retail system offers: potency degradation tracking, cross-domain risk scoring, predictive stock intelligence, compliance cascade, and staff accountability scoring.

Authentication Flow

OTP-first authentication (no passwords). Users enter email, receive 6-digit OTP via email/SMS, verify OTP, receive JWT token. Owners/admins can also use PIN-based quick login.

POST /api/v1/auth/otp/request     { email, purpose }    sends OTP
POST /api/v1/auth/otp/verify      { email, otp_code }   { token, user }
POST /api/v1/auth/otp/verify-pin  { email, pin }        { token, user }
GET  /api/v1/auth/otp/me                                 current user
POST /api/v1/auth/otp/logout                             invalidate session

5 World First Features

Tracks THC/CBD potency decline using scientifically-backed degradation models. Auto-applies price markdowns when potency drops below thresholds. Backend: potency.controller.js (266 lines).

Aggregates risk signals across 6 domains: regulatory, financial, inventory, staff, operational, customer. Detects cross-domain patterns (e.g., high voids + low stock + new staff = potential theft). Backend: risk.controller.js (482 lines) with 30s in-memory cache.

SA payday-cycle aware demand prediction (25th monthly, fortnightly). Auto-generates reorder suggestions and inter-branch transfer recommendations. Backend: stock-intelligence.controller.js (473 lines) with 5min cache.

When compliance events occur (e.g., Section 21 expiry), cascades impact: blocks affected sales, alerts managers, notifies compliance officers, updates risk score — all automatically.

Tracks staff performance: till accuracy, void/refund frequency, shift adherence, stocktake variance. Supports positive reinforcement with configurable thresholds (R200 variance default).

Backend: pos.controller.js (1,861 lines)

The largest controller. Handles: product listing with branch-scoped inventory, cart operations, checkout with payment processing, till session CRUD, daily cashup, sales history, receipt generation.

ZAR Denomination Counting

Till close requires physical cash counting: R200, R100, R50, R20, R10, R5, R2, R1, 50c, 20c, 10c, 5c. System calculates expected cash from sales and compares against physical count.

What is MDC?

The Master Digital Catalogue is the single source of truth for all products across the branch network. Operates like Amazon Seller Central — suppliers submit products, MDC reviews, tags, approves, and broadcasts to branches.

Key principle: Branches receive what MDC pushes — they don't create products locally. Inventory manager at MDC = curation & quality control, not data entry.

Product Flow

Supplier submits product (via Portal)
  --> MDC Reviews (quality, compliance docs, images)
    --> Tags: Section 21 / Lifestyle / Both
      --> Activated in MDC
        --> Broadcast to branches
          --> Branch inventory created (quantity = 0)
            --> Stock received when supplier delivers

Section 21 Medical Cannabis

  • Product level: Section 21 products are auth-gated (not visible to unauthenticated users)
  • Purchase level: Customers must upload a valid prescription
  • Verification: Documents verified against Medical Service Providers registry
  • Expiry tracking: Expired prescriptions block further purchases
  • POS enforcement: Section 21 products trigger prescription verification at checkout

Stocktake Compliance (SA GMP)

  • Photo verification required for every counted item (scale photo)
  • OCR weight detection from scale photos (Tesseract + Google Cloud Vision)
  • Variance thresholds: 5% for weighable items, 0% for countable items
  • Manager review required for unacceptable variances
  • Full audit trail with timestamps and user attribution
