How Claude Vision is Used

Each stocktake photo is sent to Claude Haiku 4.5 which:

  • Scale photos - Reads the weight displayed on the digital scale (e.g. "4.2 g")
  • Unit photos - Counts individual items visible in the photo (e.g. "7 units")

Model used: claude-haiku-4-5-20251001 (cheapest vision-capable model)

Technical Details

Image Processing Pipeline

  1. Staff captures photo via mobile camera (any resolution)
  2. Frontend compresses to JPEG 85% quality via HTML Canvas
  3. Photo uploaded to server as multipart form data
  4. Server reads file, converts to base64
  5. Base64 image sent to Claude Haiku via HTTPS
  6. Claude reads the scale display or counts items
  7. Response returned in <2 seconds
  8. If API fails, Tesseract OCR used as free fallback (scale only)

Claude's Auto-Resize Rules

  • Max dimension: 1568px (either side)
  • Aspect ratio preserved
  • A 4000x3000 photo becomes 1568x1176 (~1.84 MP)
  • Token formula: (width x height) / 750
  • Result: ~2,459 tokens per photo regardless of original size

Fallback Strategy

  • If ANTHROPIC_API_KEY not set: Tesseract OCR for scale reading (free, less accurate)
  • If Claude Vision fails: Automatic fallback to Tesseract
  • If both fail: Staff enters value manually
  • Unit counting: Claude Vision only (no free fallback - manual count if API unavailable)
