Each role gets its own assistant — with the buttons it needs, not a blank box.

Floor staff don't type questions — they tap them. Every role's chat opens with a tray of context-aware action buttons that fire pre-engineered prompts to the right agent. The user never sees the prompt; they see the answer. Typing is still available for the curious — but the demo path is buttons end-to-end.

14Implementation notes

For the engineering room — what shipping the action tray actually requires.
ConcernApproach
Action button = pre-engineered promptEach button stores the full prompt server-side keyed by actionId. Frontend sends only the actionId + role context. No prompt injection surface.
Per-role action setsStored in role_actions table, joined to user role on chat-open. Owner-tier users see merged sets when ghost-acting as another role.
Follow-up chipsReturned by the agent in a structured followups: [{label, actionId}] field. Fallback to free-text if model omits.
Tap → action confirmationDestructive actions (RP sign, AR freeze, end shift) require a second confirm tap. Non-destructive fire immediately.
Typing still allowedThe text input remains; buttons are the demo path, typing is the curious path. Both go through Maestro.
TelemetryEvery tap logged with actionId · userId · realActorId · timestamp in AuditLog. Enables "which buttons get used by which roles" reporting.
