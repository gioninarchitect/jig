UAT Scope

In Scope
  • FM login, session, RBAC, and route access.
  • Dashboard widgets and all FM-facing CTAs.
  • Tickets, deviations, assets, labels, QR, BCR, checks, mortality, and audit.
  • SOP, checklist, training, task category, and EU GMP linkage.
  • Assistant prompts and context action buttons for the FM role.
Out Of Scope Unless Enabled
  • Outbound PIN email delivery while email sending is intentionally disabled.
  • Production load testing.
  • Third-party integrations that are not connected to the UAT tenant.
  • Super Admin-only configuration workflows.
Pass Standard

A test passes only when the CTA opens, the action completes, the record survives refresh, the data is linked to the correct tenant/role/workflow, and audit evidence exists for regulated actions.

Full FM UAT Cases

  1. Open the live app.
  2. Login as an active FM account using the approved UAT method.
  3. Open /dashboard, /users, /owner, and /audit.
  4. Confirm permitted routes load and restricted routes are blocked or hidden.
Pass: user is authenticated as FACILITY_MANAGER, tenant context is correct, session persists, and Super Admin-only controls are unavailable.
  1. Open /dashboard.
  2. Review tickets, batches, tasks, risk, compliance, and operational activity.
  3. Click each visible FM dashboard CTA.
  4. Return to the dashboard and confirm no blank widgets or dead actions.
Pass: dashboard loads real data, every visible CTA opens a valid workflow, and no forbidden setup-only control is exposed.
  1. Open /tickets.
  2. Create a facility operations ticket with category, severity, owner, due date, and notes.
  3. Save, refresh, and reopen the ticket.
  4. Change status or add a note if available.
Pass: ticket persists with creator, tenant, status, timestamps, category, and audit evidence.
  1. Open /qms.
  2. Raise an operational deviation.
  3. Link SOP/control where available.
  4. Add severity, root cause placeholder, CAPA, owner, and due date.
  5. Refresh and reopen the deviation.
Pass: deviation persists, remains linked to QMS context, and creates audit evidence.
  1. Open /scan, /assets, or /containers.
  2. Validate a QR or label-linked asset/container.
  3. Confirm label identity includes asset/container name plus unique ID.
  4. Record or review a misprinted, destroyed, unused, or exception label state where available.
Pass: label state is accountable, persists, and chain-of-custody evidence exists.
  1. Open /assets.
  2. Register or review a facility asset.
  3. Confirm asset ID, asset name, category, status, and maintenance/calibration data.
  4. Trigger or review linked maintenance ticketing if available.
Pass: asset record persists and links to maintenance/ticket/audit evidence.
  1. Open /batches.
  2. Review a batch and its Batch Cultivation Record.
  3. Confirm linked checklist, SOP, daily/environmental checks, and outstanding tasks.
  4. Refresh and verify the same record state remains.
Pass: BCR is persisted, linked to required checks/tasks, and visible for FM review.
  1. Open /daily-check or /env-log.
  2. Record or review temperature and humidity checks.
  3. Check out-of-range escalation into ticket/deviation workflow.
  4. Confirm user/time accountability.
Pass: readings persist and out-of-range values create traceable workflow evidence where configured.
  1. Open /mortality.
  2. Record or review a mortality event.
  3. Confirm affected batch, location, reason, count, and user accountability.
  4. Check threshold escalation to ticket/deviation workflow.
Pass: mortality event persists, is linked to batch/location, and is auditable.
  1. Open /sop-library.
  2. Confirm FM-relevant SOPs are visible.
  3. Open /tasks and confirm task templates/checklists.
  4. Check training responsibility where available.
Pass: FM SOPs, checklist tasks, training records, and task categories are connected.
  1. Open the chat bubble.
  2. Run the prompts in the Assistant Section below.
  3. Click returned context actions.
  4. Confirm answers and CTAs stay within FM responsibilities.
Pass: assistant returns FM-specific guidance and CTAs into persisted workflows.
  1. Open /audit.
  2. Search for recent FM actions.
  3. Confirm who, what, when, tenant, entity type, and entity ID.
  4. Run or review audit verification where available.
Pass: FM actions remain traceable after refresh and audit hash chain stays valid.

Assistant Section

FM Command Layer

The strongest FM demo is to show the assistant as the Facility Manager's daily control point, not a generic chatbot. It should recognise the FM role, return FM-specific context actions, and route the user into controlled workflows that persist to the database and audit trail.

Talk track: As Facility Manager, I do not need to hunt through every module first. I can ask the assistant what needs my attention in my role. It reads my role context, points me to the right operational areas, and gives me action buttons into tickets, QMS, batches, labels, daily checks, assets, and audit evidence.

Exit Criteria

  • All FM CTAs open valid pages.
  • All create/update actions persist to the database.
  • All regulated actions create audit evidence.
  • EU GMP source/control context is visible in QMS workflows.
  • Labels include asset/container name and unique ID.
  • Ticket/deviation workflow triggers for operational exceptions.
  • FM AI assistant actions are role-appropriate.
  • No Super Admin-only controls are exposed to FM.
