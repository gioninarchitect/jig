The SMF stops being a PDF — it becomes the system.

Every section of your 47-page Site Master File v4.6 is now a live database row with its own sign-off chain, version history, drift detection, and AI-assisted authoring. The PDF stays as the regulator-handed artefact; the source-of-truth is the live system, regenerated whenever an operational change touches it.

01What changed

From paper-frozen to live-and-auditable.

BEFORE — Paper-frozen SMF

  • One 47-page PDF, version 4.6, signed Sept 2025
  • Every change requires a manual re-issue
  • Drift between SMF and reality detected at audit time, not before
  • Sign-off captured as ink + scan
  • No way to know which fields are stale until SAHPRA asks
  • Re-drafting a section = open Word doc, find the right paragraph, type

NOW — Live digital SMF

  • 58 canonical sections as live DB rows, versioned per section
  • Operational changes auto-flag affected sections stale
  • RP → DAR → AR sign-off chain enforced in code, with timestamps + signer IDs
  • Each AR approval freezes a snapshot for the regulator PDF
  • Hash-chained audit log captures every read, edit, and signature
  • AI Composer (Opus 4.7) drafts revisions in 14s — RP reviews before applying

02The 3-layer architecture

One operational substrate, three layers, each with one purpose.
Tickets
"What needs to happen" — actionable items with assignees + due dates. SMF-related tickets carry ticketType: SMF_DRIFT or RP_SIGNOFF. Routed automatically to RP / DAR / AR queues via the new "assign to person OR department" mechanism.
Specialised data
"What the work captured" — SMFSection (current state, body, sign-off chain), SMFSectionVersion (frozen snapshots), plus the full operational rich models (BayGrid, Calibrations, Deviations, Permits, Users) that feed the SMF body text via the Composer.
AuditLog
"What happened, immutably" — every action SHA-256 hash-chained. Captures real userId + ghostAsUserId (ghost mode), hash of prior entry, timestamp. Companion AICall table for every Claude API call (prompt, response, sources, tokens). SAHPRA-grade reproducibility.

05Inbound flow · Operational change → SMF stale flag

How the system catches drift before SAHPRA does. Closed-loop, no human in the trigger path.
1
User · Renae (FM) — operational action
Adds a new greenhouse via BayGrid → POST /baygrid/greenhouses → backend creates row → emits GREENHOUSE_CREATED event onto the eventBus.
2
SMF Drift Daemon · always-on listener
Catches the event. Looks up the rule table — GREENHOUSE_CREATED affects sections C.3.1 (floor plan), C.1.6 (site description), C.1.6.2 (size of site).
3
Backend · per affected section
For each section: skip if currently DRAFT (no signed chain to invalidate). Otherwise mark staleSince = now, staleReason = "New greenhouse added — floor plan + site description need re-review".
4
Backend · ticket emission
Idempotent check: no existing open SMF_DRIFT ticket for this section? Then create one — ticketType: SMF_DRIFT, priority HIGH, assignedToRole: RESPONSIBLE_PHARMACIST. Lands in Berne's queue.
5
User · Berne sees it
Berne's TicketsWidget shows the new SMF_DRIFT ticket with SLA timer. Bottleneck Radar surfaces the RP queue depth. Approvals Waiting banner appears at top of her dashboard.

06Composer flow · AI assists Berne to redraft

RP-triggered. AI proposes; RP reviews; sign-off chain restarts from DRAFT.
1
User · Berne (RP)
Opens C.3.1 → sees stale amber banner with reason → clicks "Draft with AI".
2
Backend · POST /sections/:id/compose
Pulls fresh facility data: live greenhouse register, room sizes, equipment list, water spec, key personnel, permit data. Bundles into the AI prompt context. Forbids invention via system prompt.
3
SMF Composer · Opus 4.7 + adaptive thinking
~14 seconds. Returns regulator-grade prose mentioning the actual greenhouse names. Ends with "Outstanding: <list of fields the RP still needs to gather>" when data is thin.
4
Backend · audit + persist
Logs the call to AICall with prompt, response, sources, tokens, hash-chained. Writes the AI text to composedDraft field — never to bodyText.
5
Frontend · SMF section modal
Renders the draft below the current body in a RED-bordered panel with bold "🤖 AI-GENERATED · NOT YET APPROVED" banner. Apply and Discard buttons appear.
6
User · Berne reviews
Reads the AI proposal. Verifies factual accuracy. If accurate → clicks Apply. The draft text is copied to bodyText; sign-off chain resets to DRAFT (every prior signature cleared); stale flag cleared.
7
Sign-off chain restarts
Berne clicks "RP Sign" → status RP_SIGNED. Coenie clicks "DAR Sign" → DAR_SIGNED. Ilse clicks "AR Approve & Freeze v" → AR_APPROVED. New SMFSectionVersion snapshot frozen with version number bumped, all 3 signatory IDs + timestamps.

07Outbound flow · How the SMF is consumed

Same canonical sections power four different surfaces.
1
SAHPRA Inspector — read-only view
Logs in as VIEWER. Opens /site-master-file. Sees all 58 sections grouped by chapter. Each shows: status badge (Draft / RP / DAR / AR), sign-off pip dots (rose → blue → green), stale warning if drifted, last-signed timestamp. No edit buttons. Hash-chained audit log accessible at /audit.
2
Owner Concierge — daily synthesis
Owner Brief includes "Compliance & SMF" section: how many sections stale, how many pending RP sign-off, current effective version. Numbers come from SMFSection table directly.
3
FM Compliance widget — at-a-glance
9-card compliance grid surfaces SMF-relevant indicators inline on Renae's dashboard: SOPs Due Review, Calibration Overdue, Open Deviations — each correlated to specific SMF sections.
4
Regulator-submittable PDF export
Emitted from frozen SMFSectionVersion snapshots — never from the live (potentially stale) section text. Print-ready HTML output with all signatures, version numbers, and timestamps embedded.

09Multi-unit ready

Same architecture, different content per farming unit.

The SMFSection model carries a unit field (cannabis by default). The same data model + sign-off chain + drift daemon + Composer pattern extends to:

  • Chickens — DALRRD + SAPA aligned Poultry Master File. 15 SOPs already catalogued in JSON, schema drafted, awaiting flock data to wire
  • Mielies — DALRRD + GAP aligned. Awaiting paddock register + planting plan data
  • Cattle — DALRRD + Animal Identification Act. Awaiting herd register data

Each unit gets its own canonical sections, its own drift daemon (rules tuned to that regulator), its own AI Composer with the right domain prompt. Owner Concierge synthesises across all units.
